# ADR-0001: AI導入は検査工程の一点突破で始める

- 起案: 2026-06-24 / 田中（総務部）
- 決定: 2026-07-08 / 高橋（代表取締役）・佐藤（製造部長）・田中（総務部）
- status: agreed

## 背景・課題

- AI 活用の候補テーマが複数挙がった（見積作成・外観検査・日報要約・図面英訳など）が、従業員 28 名の体制で同時に進める余力はない
- 過去に生産管理システムを全部門一斉に導入して定着しなかった経験があり（架空の経緯）、同じ失敗を避けたい
- 顧客図面・単価など区分 3 データを扱う業務が多く、テーマ選定はデータ取扱規範と両立する必要がある

## 決定

- 当社最初の AI 導入テーマは**外観検査の一次スクリーニング支援**（[[PJ-0001-検査工程のAI化]]）に限定する
- PJ-0001 の完了条件（一致率・見逃し 0 件）を満たすまで、他テーマの本格着手は行わない。ただし見積もりテンプレ整備（[[PJ-0002-見積もりテンプレ整備]]）は AI 利用の前提となるデータ整備として並走を認める

## 理由

- 判断: 効果が数字で測れるテーマから始める。理由: 検査は一致率・見逃し件数で効果を観測でき、社内の納得を得やすい
- 判断: 検査画像は社内 PC ローカル（E1）で処理する構成を採る。理由: 区分 3 相当のデータを組織の外に出さずに始められる（[データ分類マトリクス](../../../../layer1/data-classification-matrix.md)）

## 採らなかった選択肢

- **全部門一斉導入**: 教育・環境整備が分散し、どれも中途半端になるリスクが高い。過去の生産管理システム導入の教訓（架空の経緯）
- **事務作業（日報要約・翻訳）からの導入**: 着手は容易だが効果が測りにくく、「便利だが成果を説明できない」状態になりやすい
- **外部ベンダーへの一括委託**: 初年度で数百万円規模の見積もり（架空値）に対して、社内にノウハウが残らない

## 影響・フォローアップ

- [[PJ-0001-検査工程のAI化]] を起票し、完了条件を PJ ノートで管理する
- 見積・研修など他テーマは `knowledge/issues/` に課題として記録のみ行う（例: [[ISSUE-0102-新人研修の属人化]]）
- 再検討のトリガ: PoC が 2026-12 末までに完了条件を満たさない場合、テーマ選定から見直す
