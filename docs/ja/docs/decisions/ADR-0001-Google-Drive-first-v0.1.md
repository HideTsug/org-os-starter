# ADR-0001: Google Drive-first v0.1

- 起案: 2026-08-17 / maintainer
- 決定: 2026-08-17 / maintainer

## 背景・課題

従来のスターターは、導入DRIと一般メンバーの双方に、private GitHub repoを日常画面かつ知識保管先として扱うことを求めていた。履歴と機械可読構造には強いが、非エンジニアに新しい日常ツールを増やし、普段作成している場所から知識を転記させる。

最初の導入ゴールはもっと狭い。既存の社内知識源を接続し、繰り返し発生するプロジェクト質問に原本リンク付きで答えること。これを検証する前に複数SaaSへ広げると、コネクタ・権限・鮮度の挙動だけが増える。

## 決定

1. **v0.1運用プロファイルが対応する外部知識源はGoogle Driveだけ**とする。Notion・Slack・Chatwork・SharePoint・汎用ファイル接続はv0.1対象外。
2. **知識を二層化する。** Google Driveは人間が作る原本と既存ACLのSSoT。`knowledge/`は非機微なAI向け派生状態（PJ要約・issue要約・原本リンク・鮮度メタデータ）のSSoT。
3. **Layer 1はprivate repoに維持する。** `layer1/`は機械可読な規範SSoTのまま。Drive特化はLayer 2の運用動線を変えるもので、5層モデルや`Company OS as Code`規約は変えない。
4. **Drive参照はper-user OAuthに限定する。** AIは現在の利用者のDrive権限を継承する。利用者より広い参照経路を作り得るサービスアカウントとdomain-wide delegationはv0.1で禁止。
5. **最初は読取専用。** 検索・質問回答・原本リンク付きキャッチアップを先に検証し、Drive原本の自動編集はv0.1対象外。メンバーは引き続きDrive原本を編集する。
6. **内部の情報源境界はprovider-neutralに保つ。** 派生ノートには安定した情報源メタデータを持たせ、Drive固有挙動を知識スキーマ全体へ埋め込まない。別情報源はDrive動線の反復利用を確認後、新ADRで追加する。

## データ所有とフロー

```text
Google Drive原本（本文 + ACL + 改訂履歴）
        │ per-user OAuth・読取専用
        ▼
区分確認 → 抽出 → 非機微化した派生
        │
        ├─ Drive原本リンク付き回答
        └─ knowledge/ 要約 + 情報源メタデータ

layer1/ 規範 ────────────────────────▲
```

- 区分3・4の内容をGitHub、権限外の人と共有するプロンプト、ログ、PR本文、issueへ複製しない。
- 派生出力は、保持している内容の最も重い区分を継承する。
- Driveフォルダ配置はルーティングの手掛かりであり、権限の証拠ではない。現在の利用者に対するDrive実効権限を境界とする。
- 通知は変更の存在しか示さない。実装はDrive change feedを取得してから派生状態を更新する。

## 受入基準

- README・アーキテクチャ・導入ガイド・利用ガイド・AI入口がすべて、v0.1の外部情報源をGoogle Driveのみとして記述する。
- 一般メンバーはGitHubを使わず、読む・書く・聞くの3動線を実行できる。GitHubは導入DRIとAI保守の画面とする。
- PJ・issueテンプレートが、制限情報を複製せず原本URLと鮮度を記録できる。
- 2アカウント権限差テストを必須化し、開けないDrive文書の内容を回答しない。
- Drive原本の変更を検知し、全件再取込なしで派生側の鮮度を更新できる契約になっている。
- v0.1コアとして別の外部情報源コネクタを記述しない。

## 採らなかった選択肢

- **GitHubだけの日常運用** — 構造には強いが、非エンジニアの最大導入障壁を残す。
- **repo層を持たないDrive-only** — 日常入力は簡単だが、機械可読な規範SSoT、レビュー可能な派生状態、`Company OS as Code`境界を失う。
- **v0.1から複数情報源対応** — 中核の質問動線を反復利用できる前に面を広げることになる。
- **中央サービスアカウント取込** — バックグラウンド索引は容易だが、質問者の権限境界を越え得る。
- **v0.1から自動書戻し** — 読取価値を確認する前に破壊性と認可リスクを増やす。

## 再評価条件

次のどちらかを満たしたとき再評価する。

1. 外部3組織がDrive設定を完了し、少なくとも1組織が14日以内に「聞く」を2回以上使った。
2. 導入阻害になった組織から、Google Drive以外を情報源とする具体的かつ反復的な業務動線が提示された。

最初の否定シグナルは、接続後の利用者が繰り返し聞きたい質問を挙げられないこと。この場合、コネクタ追加より先にユースケースと文書網羅性を見直す。
